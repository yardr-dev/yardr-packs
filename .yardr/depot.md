Packs for yardr that are not part of yardr: each a directory at the top of this repository with a `pack.yaml`, applied to a yard with `yardr pack apply <path to the directory>`. Nothing here is compiled into yardr, and nothing here changes yardr; a pack that needs a change in the core says so in a note and stops, and that change is a bead of the yardr depot.
A pack's programs (normalize, call, mint) are written in whatever language fits them, each with the runtime it needs named in the pack's README; the gate knows no language.
A pack that can be tested has an executable program named `test` beside its `pack.yaml`, needing no network and no secret, done in seconds; the gate (`.yardr/test`) runs `yardr pack check` and then `test` for every pack. Goldens and fixtures live beside the test, under the pack's directory.
What the pack documents for its operator goes in `pack.yaml`'s setup file (`SETUP.md`), one command per fenced block, as yardr's own packs do (`packs/telegram/SETUP.md` in the yardr repository, cloned on this yard at /Users/mckean/projects/repos/yardr). `yardr docs pack-api`, `yardr docs integrations` and `yardr docs packs` say what a pack may contain.
